# Workflow 10 — Global Error Handler Preflight

## Objective

Inspect the current controlled-pilot runtime and database contract before creating the centralized n8n Error Trigger workflow.

## Proposed flow after preflight approval

```text
n8n Error Trigger
→ Normalize small failure envelope
→ Recursive case-insensitive redaction
→ Truncate oversized strings and arrays
→ Classify error code, retryability and severity
→ Reject Workflow 10 self-recursion
→ public.rpc_record_incident
→ incident deduplication and event append
→ optional notification_outbox row
→ Workflow 08
→ Gmail
```

Workflow 10 records and classifies failures. It does not re-run failed business workflows and does not send Gmail directly.

## Current known contract gaps to verify

The existing `public.rpc_record_incident(p_request jsonb)` already creates or reuses incidents, but the preflight must confirm whether it fully preserves:

- n8n execution ID and failed-node references;
- stable retryability classification;
- normalized error codes;
- public-safe metadata only;
- notification cooldown and at-most-one outbox record;
- Workflow 10 self-error markers;
- bounded fallback behavior if incident recording fails.

No replacement function will be generated until the hosted snapshot confirms the exact current contract.

## Fingerprint boundary

Expected stable inputs:

- workflow key;
- failed node;
- normalized error code;
- operation;
- institution ID where safe.

Excluded inputs:

- timestamps;
- correlation IDs;
- execution IDs;
- changing request IDs.

## Redaction boundary

Keys are redacted recursively and case-insensitively, including:

`access_token`, `refresh_token`, `authorization`, `apikey`, `api_key`, `service_role`, `password`, `client_secret`, `cookie`, `set-cookie`, `token`, and `secret`.

Values are replaced with `[REDACTED]`; original secret values are never preserved in the sanitized object.

## Retry ownership

Workflow 10 will classify retryability but will not become an independent retry owner. Existing bounded transport/business retry ownership remains unchanged.

## Recursion prevention

Errors generated by Workflow 10 must be marked and stopped from re-entering the same handler indefinitely. Incident-RPC failure will use one bounded fallback route and terminate cleanly.

## Preflight-only rule

This package intentionally contains no `workflows/10-global-error-handler.json` and no Workflow 10 migration.
